🖥️ 四福车间管理系统 · 部署到 Windows Server

适用：Windows Server 2016 / 2019 / 2022（桌面体验或 Core 均可）

一、部署总览

本系统为绿色免安装架构：只需一台装好 Node.js 的 Windows Server，把程序目录放好、启动服务、放行端口即可。数据全部在单个 data.db 文件里，备份/迁移只需复制该文件。

二、环境要求

项目要求
操作系统Windows Server 2016/2019/2022（x64）；桌面体验版或 Server Core 均可
Node.js≥ 22 LTS（必须，因使用内置 node:sqlite；23+ 已稳定，22 需 --experimental-sqlite 开关）
内存/磁盘2 GB 内存、200 MB 磁盘即可；数据库随业务增长
网络服务器与车间终端在同一局域网；需放行 TCP 8090 端口
其他无需安装数据库、无需联网；管理员权限用于放行防火墙 / 建服务

三、安装 Node.js

1到官网 https://nodejs.org 下载 LTS 安装包（选 Windows Installer .msi，x64）。

2运行安装包，一路「Next」，务必勾选 “Add to PATH”（添加到环境变量）。

3安装完成后，打开「命令提示符」或 PowerShell 验证：

node -v # 期望输出类似 v22.x.x 或 v24.x.x（≥ 22 即可） node -e "require('node:sqlite');console.log('sqlite OK')" # 若 Node 22 提示需开关，可忽略，启动脚本已加 --experimental-sqlite
若 node -v 提示“不是内部或外部命令”，说明 PATH 未生效——重新打开命令行，或手动将 Node 安装目录加入系统 PATH。

四、部署程序文件

1把整个 factory-app 文件夹复制到服务器，建议放在固定位置，例如：

C:\Workshop\factory-app\ ← 程序目录（server.js / public / data 在此）

2确认目录下含：server.js、public\、data\、start.bat、Dockerfile 等。无需执行 npm install（无任何第三方依赖）。

如用于全新部署（非从开发机迁移），可删除根目录下的 data.db（如有），首次启动会自动建库并写入初始管理员账号。

3先手动启动一次，确认能跑起来：

cd /d C:\Workshop\factory-app start.bat # 黑窗口出现 “本机访问: http://localhost:8090” 即成功 # 浏览器访问 http://localhost:8090 ，用 admin / admin123 登录
验证通过后，关闭该黑窗口，进入下一步配置开机自启（避免依赖这个手动窗口）。

五、配置开机自启（两种方式任选）

方式 A（推荐）：任务计划程序，开机自启、无需登录

  1. 「服务器管理器」→「工具」→「任务计划程序」；右侧「创建任务」。
  2. 常规：名称填 WorkshopSystem；勾选 “不管用户是否登录都要运行” 与 “使用最高权限运行”；配置为 Windows Server 对应版本。
  3. 触发器：新建 →「启动时」。
  4. 操作：新建 → 程序/脚本填 C:\Workshop\factory-app\start.bat（也可直接填 node 绝对路径 + 参数，见下）。
  5. 条件：取消“只有在计算机使用交流电源时才启动此任务”的勾选（避免断电恢复后不启动）。
  6. 确定并输入管理员密码；重启服务器验证是否自动起来。

方式 B：注册为 Windows 服务（用 nssm，更稳定、可看状态）

下载 nssm（https://nssm.cc），解压得到 nssm.exe，执行：

nssm install WorkshopSystem "C:\Workshop\factory-app\start.bat" nssm set WorkshopSystem AppDirectory "C:\Workshop\factory-app" nssm start WorkshopSystem

之后可在「服务」(services.msc) 里看到 WorkshopSystem，设为「自动」启动。

若直接以 node 注册服务，命令行参数为："C:\Program Files\nodejs\node.exe" --experimental-sqlite "C:\Workshop\factory-app\server.js"（Node 24 可省略开关）。

六、防火墙放行端口 8090

以管理员身份打开 PowerShell，执行：

New-NetFirewallRule -DisplayName "WorkshopSystem-8090" ` -Direction Inbound -Protocol TCP -LocalPort 8090 -Action Allow

若用「高级安全 Windows 防火墙」图形界面：入站规则 → 新建规则 → 端口 → TCP → 特定本地端口 8090 → 允许连接 → 全勾选 → 命名 WorkshopSystem-8090。

仅本机访问（localhost）不需防火墙；但车间其他电脑/手机通过 IP 访问必须放行 8090 入站。

七、访问与初始化

  • 服务器本机：浏览器打开 http://localhost:8090
  • 车间终端/手机：浏览器打开 http://<服务器IP>:8090（服务器 IP 用 ipconfig 查 IPv4）
  • 初始账号：admin / admin123，登录后请立即到「用户管理」修改密码并新建各岗位账号。

八、数据备份与恢复

自动备份（内置）：服务运行后，系统每天 15:00 自动把数据库备份到程序目录 backups\ 文件夹（保留最近 30 份），无需任何额外配置。
手动备份：管理员首页点「💾 备份数据库」下载 backup-日期.db；或在「用户管理 → 数据备份与恢复」点「下载当前备份」。也可直接复制程序目录下的 data.db（含 WAL 时一并复制 data.db-wal / data.db-shm）。

图形化恢复（推荐）：管理员进入「用户管理 → 数据备份与恢复」，可上传 .db 文件一键恢复，或从自动备份列表中一键「恢复 / 下载 / 删除」；恢复前系统会先自动备份当前数据以便回退。

手工恢复：先停服务，把备份改名为 data.db 覆盖原文件（建议同时覆盖 WAL/SHM），再启动服务。

若仍需额外异地备份，可用任务计划程序每日执行复制脚本（如 copy.bat）：
@echo off set d=%date:~0,4%%date:~5,2%%date:~8,2% copy "C:\Workshop\factory-app\data.db" "D:\Backup\workshop-%d%.db"

九、升级程序

  1. 停掉服务（任务计划/nssm 停止，或关黑窗口）。
  2. 用新版 server.js、public\ 覆盖旧文件；切勿覆盖 data.db（保留数据）。
  3. 重新启动服务。数据库结构变化已由程序自动迁移（启动时执行），无需手工改表。

十、常见问题排查

现象排查
启动报 “node 不是命令”Node 未加入 PATH；或改用 Node 绝对路径启动。
报错 node:sqlite 不存在Node 版本过低（<22）；升级到 22 LTS 以上，并确保带 --experimental-sqlite。
本机能开、别人打不开防火墙未放行 8090，或对方用了 localhost（应改用服务器 IP）。
端口被占用改端口：启动命令前加 set PORT=9000，或编辑 start.bat；客户端访问对应新端口。
重启后服务没起来任务计划程序“不管用户是否登录”未勾选，或 nssm 服务未设“自动”。
