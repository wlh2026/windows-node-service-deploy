🗄️ 四福车间管理系统 · 部署到绿联 4600 NAS

适用：绿联 DX4600 / 4600 系列（UGOS，Intel N5105 x86_64，支持 Docker）

一、部署总览

绿联 4600 是 x86 架构 NAS，可直接跑 Docker。推荐用 Docker 部署：进程隔离、数据挂在宿盘、开机自动重启、升级只换镜像。项目已附带 Dockerfile 与 docker-compose.yml，无需联网安装任何依赖。

方式 A：Docker（推荐）方式 B：直接安装 Node

二、方式 A：Docker 部署（推荐）

2.1 准备工作

  1. 绿联「应用中心 / 应用仓库」中安装 Docker（容器）应用。
  2. 在 NAS「文件管理」中建一个共享目录，例如 /volume1/workshop，把项目文件放进去：server.js、public/、data/、Dockerfile、docker-compose.yml。
最省事的做法：把整个 factory-app 文件夹传到 /volume1/workshop/factory-app，compose 文件里的相对路径 ./data 会自动映射到该目录下的 data。

2.2 用「Docker Compose」一键启动（图形界面）

  1. 打开绿联 Docker 应用 → Compose（项目） → 新建。
  2. 选择上面的 factory-app 目录，使用自带的 docker-compose.yml。
  3. 点「创建 / 启动」。系统会自动构建镜像并启动容器 workshop-mgmt。

2.3 用命令行启动（SSH / 终端）

在 NAS 的 SSH 终端进入 factory-app 目录执行：

cd /volume1/workshop/factory-app docker compose up -d --build # 查看日志 docker logs -f workshop-mgmt

看到 本机访问: http://localhost:8090 即启动成功。

2.4 关键配置说明（docker-compose.yml）

services: workshop: build: . image: workshop-mgmt:1.0.2 container_name: workshop-mgmt restart: unless-stopped # 开机/崩溃自动重启 ports: - "8090:8090" # 左=NAS端口 右=容器端口 environment: - PORT=8090 - DATA_DIR=/app/data volumes: - ./data:/app/data # 数据持久化到宿主磁盘
  • 改端口：把 "8090:8090" 左边改成想暴露的端口，例如 "9000:8090"，访问时用 9000。
  • 数据持久化：./data:/app/data 把容器里的 /app/data（含 data.db）映射到 NAS 磁盘，重装/升级容器数据不丢。
  • 自动重启：restart: unless-stopped 保证 NAS 重启后服务自动起来。
⚠️ DATA_DIR 必须是绝对路径：docker-compose 中已固定为 /app/data（容器内绝对路径），请勿改成相对路径或省略盘符的写法（如 /e/workshop/...），否则在 Windows 环境下 node:sqlite 可能无法创建数据库、数据落到错误位置导致「重启即丢数据」。Windows 直接运行方式（方式 B）默认使用程序目录（__dirname，本身就是绝对路径），无需手动设置。
镜像基于 node:22-bookworm-slim，启动命令已带 --experimental-sqlite，无需任何额外设置。

三、方式 B：直接安装 Node（不使用 Docker）

若不想用 Docker，可在绿联 NAS 的终端（需开启 SSH）里直接运行 Node 服务：

# 1) 安装 Node.js（以 nvm 或官方二进制为例，需 ≥ 22） # 下载 node 二进制解压到 /volume1/workshop/node，并加入 PATH # 2) 进入程序目录 cd /volume1/workshop/factory-app # 3) 启动（Node 22 需开关；24 可省略） node --experimental-sqlite server.js # 4) 后台常驻（nohup，NAS 重启后需重新执行或配合开机脚本） nohup node --experimental-sqlite server.js > /volume1/workshop/workshop.log 2>&1 &

为保证 NAS 重启后自动运行，可把启动命令加入绿联「开机启动 / 自定义脚本」，或用其“计划任务”设定开机执行。

直接运行方式下，数据文件 data.db 在程序目录；务必定期备份该文件。推荐仍优先使用 Docker 以获自动重启与隔离。

四、访问与端口映射

  • NAS 本机/同局域网：浏览器打开 http://<NAS的IP>:8090（NAS IP 在绿联「控制中心 → 网络」查看）。
  • 外网访问（可选）：在绿联「反向代理 / 端口转发」中把 8090 暴露到公网，或配合 DDNS + HTTPS 使用。生产数据建议仅限内网，外网务必加 HTTPS 与强密码。
  • 初始账号：admin / admin123，登录后请立即修改密码并新建岗位账号。

五、数据备份与恢复

自动备份（内置）：服务运行后，系统每天 15:00 自动把数据库备份到 DATA_DIR/backups 目录（Docker 方式即挂载卷里的 ./data/backups，保留最近 30 份），无需任何额外配置。
手动/图形化备份与恢复：① 管理员在系统首页点「💾 备份数据库」下载，或在「用户管理 → 数据备份与恢复」上传 .db 一键恢复、从自动备份列表一键「恢复 / 下载 / 删除」；恢复前系统会先自动备份当前数据以便回退。② 也可直接复制 NAS 上挂载卷里的 factory-app/data 目录（含 data.db）。

手工恢复：停掉容器（docker compose down），用备份覆盖 ./data/data.db（建议同时覆盖 WAL/SHM），再 docker compose up -d。

六、升级程序

  1. 用新版 server.js / public/ 覆盖 factory-app 目录（保留 data/）。
  2. Docker 方式：docker compose up -d --build 重新构建并启动；数据库自动迁移，无需手工改表。

七、常见问题排查

现象排查
容器起不来 / 反复重启看 docker logs workshop-mgmt；多半是数据卷权限问题——确保 ./data 目录 NAS 可读写。
访问提示拒绝/超时确认端口映射左边端口与访问端口一致；检查绿联防火墙/网络是否放行该端口。
数据丢失确认 volumes 已正确挂载到宿盘；不要删除 ./data 目录。
node:sqlite 报错镜像已固定 node:22 + 开关；若自行换基础镜像，请用 ≥22 且带 --experimental-sqlite。
NAS 重启后没起来确认 compose 文件含 restart: unless-stopped；绿联 Docker 需开启「开机自启容器」。
